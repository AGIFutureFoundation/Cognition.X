# Next steps — ten prompts for Opus 5

Ten self-contained sessions, ranked by value, each one a complete brief:
what to do, why it matters now, the evidence behind it, the files, the
acceptance criteria, and the commands that prove it. Copy a prompt
verbatim into a fresh Opus 5 session; each stands alone and assumes only
a clone of this repository.

They were written at **v0.45.0**, after an adversarial multi-agent review
of the platform and a set of independent checks, and are kept current as
they are worked (prompt 1 was largely completed in v0.46.0). Where a prompt rests on
a finding, the finding is stated with its file and line so the next
session can confirm it rather than trust it.

## The standing rules every session inherits

Any prompt below is subordinate to these. They are not style preferences;
they are what makes the platform's claims true.

1. **Build products are never hand-edited.** `apps/*/index.html` is
   generated from `apps/*/template.html` by `tools/build_*.py`. Edit the
   template or the builder, then rebuild. CI fails on drift.
2. **`block_id`s are never reused or renumbered.** Supersede; never
   rewrite. A MAJOR version does not license breaking them.
3. **Never overwrite a non-empty source field.** `normalize_blocks.py`
   fills empties only; the sole historical exception was two exact
   placeholder sentences, under a guard.
4. **The honesty stances travel with the content**, verbatim: simulation
   is never certification; no union local or chapter numbers anywhere
   (the regional council is the front door); access profiles are chosen
   supports, never diagnoses; nothing leaves a page on its own; a
   signature proves integrity and key possession, identity is confirmed
   out-of-band; the Willie L. Brown Jr. Institute disclaimer is carried
   word for word.
5. **Every claim in the docs must match the code.** If you cannot make
   the claim true, change the claim.
6. **Prove it before you ship it:** `python3 tests/test_platform.py`
   (Python-only, runs in CI) and, for any app change,
   `node tests/browser/smoke.js` (needs Playwright + Chromium).

## 1 — Finish the Education OS visual pass *(largely done in v0.46.0)*

**The story so far.** The v0.1.0 import captured the application's
JavaScript — 149 view definitions and 143 renderers, about 8 MB — but
neither its HTML shell nor its stylesheet, so the flagship never ran:
it threw on boot at `buildNav()` and printed a stray unwrapped
`var DATA = {…}` block as visible page text. **v0.45.0** generated the
missing shell from the app's own `VIEWS` array, so it boots and renders.
**v0.46.0** restored the design system the same way — tokens recovered
from the app's own documented brand values (“Gold — first contact”
`#B8871F`, “Teal — application” `#1E7A72`, “Ink — the keystone”
`#0E1E2E`) and its `DATA.vizTok` fallbacks, ~35 base component rules
generated by the builder, light and dark on all three theme paths, every
text pair verified at 4.5:1 or better, and a design-system guard in
`tests/test_platform.py`.

**What remains — the objective of this session.** A full 149-view sweep
never completed in the environment that did the work: a representative
sample (every sixth view, 25 of 149) came back with zero errors, zero
empty views and zero horizontal overflow, but **124 views are
unverified**.

**Steps.**
1. Walk every view. Record, per view: renderer errors, content that
   overflows horizontally or collapses, and any class emitted by a
   renderer that has no rule (the covered set is `EDU_REQUIRED_RULES` in
   `tests/test_platform.py`; the app also injects ~16 KB of its own CSS
   at runtime, which is deliberately not duplicated).
2. Fix the **CSS, in the builder** — never the renderers, never
   `index.html`.
3. Consider an offline-embedded display font: the app's own injected CSS
   asks for `font-stretch:125%` on `--display`, which needs a variable
   font the import did not carry. Any font must be embedded, not
   fetched — the no-network stance is enforced by
   `tests/test_platform.py`.
4. Extend `EDU_REQUIRED_RULES` with whatever new classes you cover, so
   the guard keeps pace.

**Acceptance.** All 149 views render with zero page errors and no
horizontal overflow at 1280px and at 400px; every class the renderers
emit has a rule; both themes still pass contrast; the app still opens
from `file://` with no network; both suites pass.

**Verify.**
```bash
python3 tools/build_education_os.py && python3 tests/test_platform.py
node tests/browser/smoke.js
```

## 2 — Author the 24 missing credential names *(drafted in v0.52.0 — proposed to the board, not yet adopted)*

**Why.** A credential should name an accomplishment. **1,228 rows — 7% of
the dataset, 24 tracks across five community packs — name their
credential with the bare band level “Practitioner”.** The headline
“1,394 credentials” counts that word as if it were a credential; there
are 1,393 real ones. A learner completing one of those tracks would be
issued — and the Records Office would cryptographically sign — a
`cx-credential/1` record whose credential reads “Practitioner”. The
signature would be valid and the claim meaningless.

The defect arrives in the v0.1.0 import
(`data/source/Cognition.X_all_blocks.csv`, 1,228 rows already affected)
and passes through untouched because the pipeline correctly never
overwrites a non-empty source field. Full write-up:
`docs/DATA_REVIEW.md`, Finding 6.

**Objective.** Author 24 credential names and lower the ratchet.

**Steps.**
1. List the affected tracks:
   ```bash
   python3 -c "
   import csv;from collections import defaultdict
   rows=list(csv.DictReader(open('data/blocks.csv',newline='',encoding='utf-8')))
   d=defaultdict(set)
   for r in rows:
     if r['credential'].strip() in {'Explorer','Builder','Practitioner','Lead'} and r['track']:
       d[(r['pack'],r['track'])].add(r['credential'])
   [print(k) for k in sorted(d)]"
   ```
2. Name each in the shape those packs already use — *Care Explorer*,
   *Oral Health Peer*: a person and a capability, never a level word,
   never a job title the credential cannot confer.
3. Apply them **through the pipeline**, not by editing `blocks.csv`
   directly: add a `data/promotions/` entry (or extend the existing
   one for that pack) that sets `credential` per track, and make the
   correction explicit — this is the one deliberate exception to
   fill-empty-only and it must be visible in the diff and the changelog.
4. Note the one split-credential track: *Preventive Health & Everyday
   Care → “The mouth, understood”* already carries *Oral Health Peer*
   on its first theme and “Practitioner” on the other 45 rows. Unify it.
5. Lower `KNOWN_LEVEL_WORD_CREDENTIAL_ROWS`,
   `KNOWN_LEVEL_WORD_CREDENTIAL_TRACKS` and
   `KNOWN_SPLIT_CREDENTIAL_TRACKS` in `tests/test_platform.py` to the
   new reality (to zero if fully fixed), and rewrite Finding 6 as
   resolved.

**Guardrail.** `docs/GOVERNANCE.md` reserves authored curriculum content
to the review board. Treat this as drafting for the board: the names go
in the PR body for review, and the PR says plainly that they are
proposed, not adopted.

**Acceptance.** `docs/DATA_QUALITY.md` shows 0% level-word credentials;
the ratchet is lowered; `validate_blocks.py` and `test_platform.py` pass;
no `block_id` changed.

## 3 — Close the verified review findings

**Why.** The v0.45.0 review surfaced defects that are real but larger
than one release could absorb. They are listed here rather than quietly
dropped.

**Objective.** Work the list below, verifying each against the code
before fixing it — several were reported by an agent and are *claims*,
not established facts. Fix what survives; write down what does not and
why.

**The list** (file and line as reported; confirm before acting):

| Area | Where | Claim |
|---|---|---|
| Re-render destroys listeners | `apps/louisiana/template.html:2174` | `el.innerHTML +=` at the end of the Student standing widget re-parses the panel and drops every listener bound above it |
| Focus loss | `apps/louisiana/template.html:1711` | `saveR()` schedules a full `renderRoles()`, replacing `#rolebody`, so every select/checkbox/reorder press destroys the control the user is on |
| Unescaped ids | `apps/louisiana/template.html:2308` (also 2121, 2309, 2449, 2459, 2513) | learner and queue ids are interpolated into HTML attributes without `esc()` |
| Parent swarm reads the wrong learner | `apps/louisiana/template.html:2022` | Parent agents read `swarmMe()` (the Student's `R.me`) while Parent widgets read `R.child`, so the arbitrated call can name a different child |
| Access bias cancelled | `apps/louisiana/template.html:1852` | `accessOf` combines `stepBias` with `Math.min`, so any second profile cancels a positive bias |
| Practice vs witnessed | `apps/louisiana/template.html:1055`, `:2654` | the signed record asserts “witnessed per the pack's checks”, but self-recorded practice credits the same counter the Records Office signs — including seeded demo learners |
| Consent gate is UI-only | `apps/louisiana/template.html:2950` | the export handler never re-reads the checkbox; only the `disabled` attribute gates it |
| Silent storage failure | `apps/louisiana/template.html:676` | `store()` swallows write failures, so trust-list imports, revocations and ledger credits report success after persisting nothing |
| Pack Studio fields unbound | `apps/flow-hub/template.html:377` | “Pack name” and “Notes” carry no `data-ps` attribute, so `psBind()` never binds them |
| Deep-link mismatch | `apps/flow-hub/template.html:1140` | the `#track` regex wants `SLUG/PREFIX` while cross-app callers emit a bare slug |
| Slug collision | `tools/normalize_blocks.py:92` | `slug_for`'s acronym fallback can map two packs to one slug; ids stay unique so every validator passes while slug-keyed lookups merge |
| Band coverage unchecked | `tools/validate_blocks.py:55` | the documented “10 themes × 5 bands” is only enforced as “50 rows, 10 themes” |
| Triage category never computed | `tools/evidence_triage.py:13` | an “UNUSED” category is documented but `main()` never produces it |

**Acceptance.** Each row is fixed, or recorded in `docs/DATA_REVIEW.md`
with the reason it was rejected. Regression coverage added to
`tests/test_platform.py` or `tests/browser/smoke.js` for every fix.

## 4 — Finish the WCAG 2.2 AA audit *(done in v0.53.0 — see docs/ACCESSIBILITY.md for what remains)*

**Why.** v0.33.0 shipped a first pass (skip links, `lang`, reduced
motion, aria-labels). The audit itself was never completed, and the
review found concrete gaps: click-only `div`/`span` controls (the
Assessor queue header at `apps/louisiana/template.html:2449`; Trades
Network pack chips at `apps/trades-network/template.html:692`), the
Records Office verdict written into a plain `<span>` with no
`role="status"` (`:2676`), form controls generated inside widget
`innerHTML` with no accessible name (`:2120`), and pulse re-renders
(Network OS at 20s, swarms at 10s) that destroy a focused control
mid-interaction.

**Objective.** A real audit with a written result, not a sweep of
plausible fixes.

**Steps.** Work each app keyboard-only, then with a screen reader. For the
pulse problem, prefer surgical updates over `innerHTML` replacement, or
skip the re-render while the panel contains `document.activeElement`.
Record the audit in `docs/ACCESSIBILITY.md`: what was tested, what
passed, what failed, what remains and why.

**Acceptance.** Every interactive element is reachable and operable by
keyboard with a visible focus ring and an accessible name; no re-render
steals focus; status messages are announced once; the audit document
lists any remaining AA gap explicitly rather than implying none.

## 5 — Standards mapping and transfer-check rubrics *(done in v0.56.0 — two frameworks, 30 rubrics; see docs/STANDARDS.md)*

**Why.** Two Phase 1 items with real classroom consequences are still
open: no block maps to an external standard, and no transfer check
carries a rubric — so an assessor's “would transfer” judgement has no
shared anchor beyond the three-line rubric in the app.

**Objective.** Add both as canonical data, generated and validated.

**Steps.**
1. `data/standards/<framework>.json` mapping `block_id` → codes, for at
   least two packs (Common Core / NGSS for K–12; the Louisiana K–12
   program already cites LDOE codes in
   `data/louisiana/k12_program.json` — start there, it is the shortest
   honest path).
2. `data/rubrics/` keyed by theme: pass evidence, two or three common
   failure modes, an assessor note.
3. Extend `validate_blocks.py` to check referential integrity (every
   mapped id exists; every rubric theme exists) and add coverage columns
   to `tools/data_quality.py`.
4. Surface rubrics in Assessor Mode and in the printable workbooks.

**Guardrail.** Standards codes are factual claims about external
documents. Cite the document and its version, and carry the same caveat
the K–12 program does: *verify each code against the current documents
before classroom use.*

## 6 — Pay down the description debt without inventing content

**Why.** `docs/DATA_QUALITY.md`: **6,200 rows (37%) have no description
at all**, and **10,500 (62%) share one sentence across five bands with an
“— at ‹band›” suffix** — 2,098 distinct stems covering 10,500 rows. The
roadmap calls band-differentiated descriptions “the largest
content-quality lift”, and it is right.

**Objective.** Make descriptions say something different at each band,
starting where the leverage is highest.

**Steps.**
1. Rank the 2,098 stems by rows covered and by pack importance; start
   with the core spine (the packs every parish plan draws on).
2. Write per-band descriptions that differ in *what the learner does*,
   not in adjectives — the band is already in the `level` column.
3. Generate through the pipeline (pack specs or a `data/promotions/`
   entry), never by editing `blocks.csv`.
4. Leave the 6,200 empty rows honest if you cannot author them: the
   irregular foundation library is documented debt
   (`docs/DATA_REVIEW.md` §2), and a generated filler sentence would be
   worse than an empty field.
5. Watch the dashboard move; it regenerates in CI.

**Acceptance.** Band-suffix percentage falls measurably with no drop in
description coverage; every changed row is traceable to a spec or
promotion; no `block_id` changed.

## 7 — Inject the canonical layers back into the Education OS template

**Why.** Four fact bases are canonical data now
(`data/louisiana/fact_base.json`, `data/louisiana/k12_program.json`,
`data/wlb/institute.json`, and the sector library in `blocks.csv`) — but
the Education OS template still carries its own copies, so the same facts
live twice and can drift. The roadmap's remaining pipeline item is to
inject the canonical layers at build time and delete the embedded ones,
shrinking an 8 MB template.

**Objective.** One source of truth per fact, with the template getting
smaller.

**Steps.** Extend `tools/build_education_os.py` to overwrite
`DATA.regions`, `DATA.regionHubs`, `DATA.parishes`, `DATA.wlb`,
`DATA.wlbPrinciples`, `DATA.lak12` and `DATA.lak12Threads` from the
canonical files (the existing `sectorBlocks` overlay is the pattern).
Then remove the embedded literals from the template, one at a time,
rebuilding and sweeping the affected views after each removal.

**Acceptance.** `tools/extract_fact_bases.py` still reproduces the
canonical files byte-for-byte *before* the literals are removed (run it
first and commit any diff separately); after removal, the app renders
every affected view identically; the template shrinks; all tests pass.

**Guardrail.** Removing a literal the app still reads is how you break
149 views at once. Remove one, rebuild, sweep, commit.

## 8 — W3C Verifiable Credentials / Open Badges 3.0 envelopes *(done in v0.60.0 — see docs/CREDENTIALS.md)*

**Why.** The Records Office issues `cx-credential/1` — a format this
project invented. It is honest and it verifies, but nothing outside
Cognition.X can read it. The roadmap's last federation item is envelope
alignment, and it is what makes a learner's credential portable beyond
the platform that issued it.

**Objective.** Emit a standards-shaped envelope alongside the native
record, without weakening any existing guarantee.

**Steps.** Map `cx-credential/1` onto a VC 2.0 / OB 3.0 `credentialSubject`
(the learner is pseudonymous by design — keep it that way), keep the
existing ECDSA P-256 signature path, and carry the `rid` as the
credential id so `cx-revocation/1` keeps working. Verification must still
be offline and must still produce the four grades: invalid,
valid-but-untrusted, trusted-by-name, revoked.

**Acceptance.** A record round-trips through a third-party VC validator;
the native path is unchanged; the honest-scope wording still says
plainly that a signature proves integrity and key possession while
identity is confirmed out-of-band.

## 9 — Learner state that survives: IndexedDB and cross-app continuity *(ledger and office key durable in v0.57.0–v0.58.0; trust lists and cross-app continuity remain)*

**Why.** The ledger, the queue, the trust list and the revocation lists
all live in `localStorage`, which is size-limited, synchronous, and
silently lossy — `store()` already swallows write failures
(finding in prompt 3). A hall running a real cohort will hit this. The
roadmap lists IndexedDB migration and cross-app sync as open.

**Objective.** Durable local state, with the consent-first stance intact.

**Steps.** Migrate to IndexedDB behind the existing accessor functions
(`llLoad`/`llSave`/`trustLoad`/`revlistsLoad` are already the seam), with
a one-time import of existing `localStorage` data and a fallback when
IndexedDB is unavailable. Surface write failures instead of swallowing
them. Keep the export box the only exit: no sync service, no network.

**Acceptance.** A cohort-sized ledger (hundreds of learners, thousands of
evidence rows) saves and reloads; a simulated quota failure is reported
to the user, not silently dropped; existing browsers migrate without loss;
`tests/browser/smoke.js` extended to cover migration.

**Acceptance.** Someone who has never seen this repository can run a

## How these were chosen

Prompts 1, 2 and 3 come from defects found by the v0.45.0 review and the
new invariant suite — the Education OS never having rendered, and 1,228
rows naming a level where a credential belongs, were both discovered by
tests written in that release, not by reading. Prompts 4–9 are the
roadmap's own open items, re-ordered by what a real cohort would hit
first. Prompt 10 is the gate everything else is waiting on.

The honest summary of the platform at v0.45.0: the pipeline is sound and
reproducible, the working models do what they claim, the stances hold
under test — and the two largest gaps are a flagship that needs its
design back and a body of curriculum content that has never been read by
an educator.
