# Platform Model

**Cognition.X Platform** is the capstone app — a single offline HTML
file that presents the whole platform as one working model:
[`apps/platform/index.html`](https://github.com/AGIFutureFoundation/Cognition.X/blob/main/apps/platform/index.html)
(~32 KB; opens locally, zero network calls).

Like every other app it is a **build product** — regenerated by
[`tools/build_platform.py`](https://github.com/AGIFutureFoundation/Cognition.X/blob/main/tools/build_platform.py)
from `data/manifest.json`, `data/blocks.csv` and `VERSION`, never
hand-edited.

## The four views

### The Model

Live dataset totals plus a clickable **ten-node system map**: the
dataset and pipeline on the left, the six apps, the four working
models that run in the learner's browser (learner ledger, flow
engine, assessor loop, records office), the Network OS — and the
**evidence loop** drawn as a dashed gold arc back through the review
board to the dataset, labeled the way the platform means it: *what
happened, by consent → what gets revised, by review*. Clicking any
node explains what it is and how it is verified.

### Run the Loop

The complete learning loop, executed in the page with the platform's
**real mechanics on labeled demo data** — six stages that gate in
sequence:

1. **Enroll** — one demo learner on a genuine Louisiana OS track,
   seeded at 47/50 checks so a single run can reach a credential.
2. **A flow session** — the real flow state machine (warming up /
   in flow / cruising-stretch / overloaded-shrink / break called at
   the 8-move cadence), with the automations' answers shown live.
3. **Witnessed checks** — the assessor rubric (*real material ·
   independent at band · would transfer*); confirmations credit the
   ledger, not-yet debriefs credit nothing, and the credential fires
   automatically at **exactly the 50th check** — no button awards it.
4. **Sign the record** — a Records Office keypair is generated by the
   browser's own WebCrypto and the earned credential issued as a
   genuinely-signed **cx-credential/1** record (ECDSA P-256; only the
   public key is in the record; the payload is marked `DEMO RUN`).
5. **Verify — three grades** — as-is (△ valid, key untrusted), a
   tampered copy (✗ invalid — one changed character breaks the
   signature), and after trusting the office (✓ signed by trusted
   office, by name).
6. **Close the loop** — the run's own **cx-evidence/1** aggregate:
   per-track counts, no names, in the same format
   `tools/evidence_triage.py` reads for the review board.

The run lives only in the page's memory — nothing is stored, nothing
is sent; *Reset the run* starts over.

### The Apps · The Stack

Doors into all six apps by relative link; the full regeneration
command list; the eight honesty stances gathered in one place; and
links into the system review, roadmap, governance and changelog.

## What "working model" means here

Every stage runs the **same rule the platform ships** — the flow
thresholds, the 50-check credential threshold, the signing and
verification code paths, the evidence format — on data that is
clearly labeled demo. Nothing is simulated by a lookup table, and
nothing pretends to be a real learner, office, or export.
