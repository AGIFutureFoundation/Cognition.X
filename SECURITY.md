# Security policy

## What the software is

Six single-file HTML applications that run entirely in the browser: no
server, no account, no telemetry, no network request of any kind. Every
app carries a Content-Security-Policy that makes the browser refuse
every connection (`connect-src 'none'`), embeds its typefaces, sends no
referrer, and allows no `eval`. What a person enters stays in that
browser's local storage until they erase it; the only things that ever
leave are files a person exports. The full review is
[`docs/COMPLIANCE_REVIEW.md`](docs/COMPLIANCE_REVIEW.md); the control
register is [`docs/CONTROL_REGISTER.md`](docs/CONTROL_REGISTER.md).

## Supported versions

The latest release on `main` (see [`VERSION`](VERSION) and the
[changelog](CHANGELOG.md)). Every release is squash-merged with CI green
and rebuilt byte-for-byte from source in CI. Earlier releases are
archived, not patched: take the latest file.

## Verifying a file you were given

The apps travel by USB stick, e-mail and file share. Verify that the file
you hold is the file this repository released:

    sha256sum -c apps/CHECKSUMS.sha256

from a clone or download of the repository at the same version. The sums
are regenerated by CI on every build and committed with the builds.

## Reporting a vulnerability

Report privately to the maintainers through GitHub's private
vulnerability reporting on this repository (Security → Report a
vulnerability), or by e-mail to `security@agifuturefoundation.org` if
GitHub reporting is unavailable. Please include the app, the version from
its footer, the browser, and steps to reproduce. Do not open a public
issue for a security report.

What to expect: acknowledgement within five business days; a fix or a
documented decision within thirty days for anything that lets data leave
a page, alters a signed record without detection, or breaks the
credential threshold; credit in the changelog if you want it. There is
no bug bounty.

## Threat model in one paragraph

An attacker who controls the device or the browser profile controls
everything in it — that is true of any local-first software, and the
answer is the host's device policy, not a feature. Against everyone
else: nothing is transmitted; the Records Office private key is a
non-extractable WebCrypto key that no script or export can read; records
are signed and verify offline with tamper detection; pasted data
(ledgers, trust lists, revocation lists) is sanitized as third-party
input; every `file://` page in Chromium shares one origin, so each app
namespaces its keys and hosting over https gives each its own origin.

## Out of scope

Reports about the demo data, the reference missions in the Education OS,
or the honesty of a claim in a document are welcome as ordinary issues.
